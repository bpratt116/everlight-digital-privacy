Honeycomb: Couples Budgeting

A zero-based envelope budgeting app for married couples on iOS. Real-time spouse sync, an honest pricing model, and optional Plaid-powered bank-transaction import so you spend a few minutes a week on money instead of an hour.

Status: In active development. TestFlight beta and App Store submission planned for 2026. Sprint 0 (manual-entry budgeting + iCloud household sync) is shipped in code. Plaid integration is Sprint 1 and requires Plaid Production approval — this page accompanies that application.

What Honeycomb Does

Honeycomb is built for one specific job: helping a married couple plan and track every dollar of their income together, in the same shared budget, in real time, from two phones.

  • Zero-based envelope budgeting. Every dollar of income is assigned to a named envelope (Groceries, Rent, Gas, Sinking Fund, etc.). When an envelope is empty, spending stops.
  • Real-time spouse sync. Both spouses see the same envelopes, the same balances, and the same transactions the moment either of them logs a charge. Built on a private iCloud CloudKit shared zone; no third-party social layer.
  • Per-transaction assignee. Every transaction is tagged as His, Hers, or Joint, so the household dashboard can show contribution and spending splits without spreadsheets.
  • Sinking funds, rules, and recurring transactions. Predictable bills, irregular savings (car repair, Christmas, insurance premium), and rule-based payee → envelope categorization are all first-class.
  • Plain-English insights and benchmarks. Honeycomb compares the household's spending against published guidance (Dave Ramsey, BLS Consumer Expenditure Survey, USDA food plans, CFPB) and offers gentle tips when an envelope is consistently overrun.

Who Honeycomb Is For

The target user is a U.S.-based married couple in their 20s, 30s, or 40s who:

  • Have rejected the spreadsheet but also rejected Monarch's "investment dashboard" sprawl and YNAB's $99/yr price.
  • Have previously used Dave Ramsey's EveryDollar or Mint and want something that respects an envelope model.
  • Want their spouse on the same screen, with the same data, on day one — not as an upsell.

Honeycomb is U.S.-only at launch (Plaid coverage and bank routing assume USD).

How Plaid Is Used Inside Honeycomb

Plaid is an optional feature reserved for the paid "Pro household" tier. The free tier is a complete manual-entry budgeting app — Plaid is not required to use Honeycomb.

Plaid products requested

  • Link — for the bank connection UX.
  • Transactions — the only data product Honeycomb actually consumes. Honeycomb fetches the transaction stream from the user's connected checking, savings, and credit card accounts, then matches each transaction to a budget envelope (or queues it for the user to assign).
  • Auth and Identity are not requested. Honeycomb does not initiate ACH transfers, does not move money, and does not need account/routing numbers.
  • Investments, Liabilities, Income, and Assets are not requested. Honeycomb is a zero-based budgeting app — net-worth tracking and investment dashboards are deliberately out of scope.

End-to-end flow

  1. The user (Pro tier only) taps "Connect a bank" inside Honeycomb's Household settings.
  2. Plaid Link runs inside the app and returns a public_token.
  3. Honeycomb's iOS client posts the public_token over HTTPS to honeycomb-finance-worker, a Cloudflare Worker we operate. The Worker exchanges the public token for an access_token using our Plaid client secret, which is stored only as a Worker secret and never embedded in the iOS binary.
  4. The Worker stores the encrypted access_token keyed by the user's CloudKit user record ID. It returns only an opaque connection ID to the client.
  5. On schedule (and on user pull-to-refresh), the Worker calls /transactions/sync, returns the delta to the iOS client, and the client writes those transactions into the household's CloudKit shared zone where both spouses see them.
  6. The user (or our rule engine) assigns each new transaction to a budget envelope. The envelope's "spent" total updates in real time on both phones.

Data Honeycomb stores from Plaid

For each imported transaction Honeycomb keeps: amount, currency, merchant name as returned by Plaid, posted date, account name (e.g. "Chase Checking ...4321"), and a Plaid-assigned category that we then map to the user's envelope. Honeycomb does not store the user's bank login credentials, full account numbers, routing numbers, balance history beyond the most recent balance, or any investment, loan, or identity data.

Where the data lives

  • iOS device. Transactions render from the household's CloudKit shared zone, which is encrypted at rest by iCloud.
  • CloudKit (the user's iCloud). Honeycomb has no third-party server-side user database. Budget data, envelopes, and transactions live inside the user's iCloud account and the CloudKit shared zone they explicitly invite their spouse into via Apple's CKShare flow.
  • Cloudflare Worker (honeycomb-finance-worker). Stores only the encrypted Plaid access_token and a small cursor for incremental sync. No transaction history, no PII, no merchant data is retained server-side once delivered to the iOS client.

Retention and deletion

If a user disconnects a bank inside Honeycomb, the iOS client calls /item/remove on Plaid via the Worker and the Worker immediately deletes the stored access_token. Transactions already imported into the user's CloudKit data stay with the user (they own their budget history) unless the user deletes the household or their Apple ID. There is no marketing pipeline, no analytics broker, and no sale of data — see the master privacy policy.

Security

  • All client ↔ Worker traffic is HTTPS / TLS 1.2+.
  • Plaid client secrets are stored as Cloudflare Worker environment secrets — never shipped in the iOS binary, never returned to the client.
  • Plaid access_tokens are encrypted at rest using Worker KV encryption and keyed per-user.
  • Spouse sharing happens via Apple's CKShare invite flow inside Honeycomb. The shared zone is only visible to the inviter and the explicitly invited spouse — no public discovery, no friend graph.
  • Honeycomb has no advertising SDK, no analytics SDK that ingests financial data, and no third-party trackers.
